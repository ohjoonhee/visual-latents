# E0 — status after first pilot

**Date:** 2026-08-13 · **Harness:** `e0_mentis/` · **Benchmark:** MentisOculi (Apache-2.0, `master`)

Companion to `DIRECTION_2026_08.md`. What E0 is, what was found building it, and what the
first pilot actually established.

---

## What E0 asks

Give the model the *same* ground-truth intermediate state in different formats and see which
formats it can use. Four arms:

| Arm | What the model is handed | Role |
|---|---|---|
| (a) none | the puzzle image only | floor |
| (b) pictorial oracle | GT intermediate state rendered as an image | tests imagery *utilization* |
| (c) spatial oracle | GT state as structured symbols | H2's arm |
| (d) verbal oracle | GT state as fluent prose | CapImagine's format |

The point is that arm (b) isolates **imagery utilization** from **imagery generation**. A model
can fail at "thinking in pictures" either because it draws the wrong picture or because it cannot
use a correct one. Handing it the correct picture separates those.

---

## Finding 1 — the true oracle arm was never run

MentisOculi ships a prompt named `visual_cot.txt` for **all five tasks**. Its closing lines:

> The following images correspond to intermediate images in the reasoning process.
> You must use them to obtain your answer:
> `<images visual cot>`

Those are the ground-truth intermediate images **for the puzzle being solved**. The strategy
appears **nowhere** in `results/results_table.csv`.

The arm that *is* reported — `icl_intermediate_images`, Rush Hour only — is **few-shot ICL over
other puzzles' worked examples**, not ground truth for the puzzle under test. So the paper's
"fail to leverage even ground-truth visualizations" claim has a stricter reading that the released
data does not cover, and the prompt to test it was written by the authors and left unused.

## Finding 2 — the tasks form a symbolizability gradient

Read off each task's `metadata.json`. This is what makes arm (c) constructible or not:

| Task | Ground truth recorded | Symbolizable? |
|---|---|---|
| hinge-folding | `rotation_sequence: "A 90"`, `shape_chain: ['square','triangle']`, `rotation_angles: [90]` | **fully** — the solution *is* a symbol string |
| paper-fold | `grid_size: 3`, `num_folds: 5`, `fold_types: ['horizontal','diag_neg','diag_pos','diag_pos','vertical']` | **partly** — fold sequence yes; the five answer options exist only as rendered images |
| form-board | `pieces: [{piece_id, image, is_solution, label}]`, `solution_pieces: ['B']` | **barely** — piece geometry exists only as pixels; no polygon coordinates anywhere |

That is an ordered series in how hard the state is to write down. The verbalization-gap curve can
come from task structure rather than an artificial complexity knob — and the benchmark's own
coverage corroborates it: `simple_text` exists **only** for Rush Hour, a 6x6 grid.

## Finding 3 — the pilot validated the harness and disqualified the model

Qwen3-VL-4B-Instruct, level 1, n=30 per cell, greedy decoding. Scored with MentisOculi's own
`evaluate_responses.py`.

| Task | arm (a) `simple` | arm (b) `visual_cot` | random |
|---|---|---|---|
| paper-fold | 0.100 (3/30) | 0.100 (3/30) | 0.200 |
| hinge-folding | 0.500 (15/30) | 0.500 (15/30) | — |
| form-board | 0.000 (0/30) | see below | 0.032 |

Oracle and baseline are identical. **That is not evidence that the oracle fails to help.** The
model emits a *constant answer*:

- paper-fold: `"C"` on all 30 puzzles, both arms — 29/30 answers identical across arms
- hinge-folding: `"A 90"` on all 30 puzzles, both arms — 30/30 identical

`0.500` on hinge-folding is just `"A 90"` being right half the time at level 1. `0.100` on
paper-fold is below the 0.200 random baseline because a fixed `"C"` happens to hit 3 times.

The oracle images *were* attached — `n_images` goes 1 -> 2 between arms — so this is not a
plumbing bug. The model simply is not engaging the input. **Oracle utilization cannot be measured
in a model that does not read the puzzle.** form-board is the one task where output varied
(13 distinct answers across 30 puzzles), and it scored 0.000.

For scale: Gemini-3-Pro scores 0.900 on paper-fold level 1. A 4B model is far below the floor
where this comparison carries information.

**Conclusion: the harness works end to end; the model does not.** E0 needs either the local 7B
checkpoint or frontier API access before its numbers mean anything.

## Two upstream defects found while building

1. `evaluate_responses.py` requires an embedded per-response `metadata` field, though
   `datasets/README.md` calls it optional — there is no `puzzle_dir` fallback for ground truth.
2. form-board's metadata records `cot_images: ["1_cot_00.png"]`; the file on disk is
   `cot_00.png`. The puzzle-id prefix exists in metadata only, and crashes any consumer that
   trusts it. Worked around by trying the prefix-stripped basename.
